# Linux Build Guide

[简体中文](build_linux.md) | English

## Current Build Model

Linux builds use Qt 5 UI, a Google WebRTC static package, an optional FFmpeg shared/dev runtime package, static `spdlog`, and static `libvterm`. The project requires CMake 3.21+, C++20, and GCC/G++ 11+.

| Architecture | WebRTC target | Preset | Default FFmpeg directory |
| --- | --- | --- | --- |
| x64 | `libwebrtc::linux_x64_m144_gnu` | `linux-x64` | `third_party/ffmpeg-builds/ffmpeg-n8.1-latest-linux64-lgpl-shared-8.1` |
| arm64 | `libwebrtc::linux_arm64_m144_gnu` | `linux-arm64` | `third_party/ffmpeg-builds/ffmpeg-n8.1-latest-linuxarm64-lgpl-shared-8.1` |
| armhf | `libwebrtc::linux_armhf_m144_gnu` | `linux-armhf` | `third_party/ffmpeg-builds/ffmpeg-n8.1-latest-linuxarmhf-lgpl-shared-8.1` |

Notes:

- Linux uses the GNU libstdc++ ABI WebRTC package by default. Use `-DWEBRTC_LINUX_STL=libcxx` only when the matching local package exists.
- Linux statically links `libstdc++` and `libgcc` by default. Control this with `-DSTATIC_LINK_LIBSTDCPP=ON/OFF`.
- The FFmpeg backend is enabled by default. A development build emits an explicit warning and falls back to WebRTC's internal codecs when headers or `.so` runtime files are absent. Official packaging forces it on and requires complete runtime and source/license metadata.
- Qt system translations are auto-detected from `qmake -query QT_INSTALL_TRANSLATIONS`, the Qt install prefix, `/usr/share/qt5/translations`, and related paths. Override with `-DAIRAN_QT_TRANSLATIONS_DIR=/path/to/translations`.

Ubuntu 18.04 defaults to `g++` 7.5, which cannot compile the current WebRTC m144 headers. The minimum CMake version is 3.21+; GCC/G++ must be 11 or newer.

### Install GCC/G++ 11 on Ubuntu 18.04

If your system repository does not provide `gcc-11` / `g++-11`, enable the Ubuntu Toolchain PPA:

```bash
sudo apt install software-properties-common
sudo add-apt-repository ppa:ubuntu-toolchain-r/test
sudo apt update
sudo apt install gcc-11 g++-11
```

When the default compiler is too old, override these cache variables from `CMakeUserPresets.json`:

- `CMAKE_C_COMPILER`: `gcc-11`
- `CMAKE_CXX_COMPILER`: `g++-11`

If you want the system default `gcc` / `g++` to point to 11, register alternatives:

```bash
sudo update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-11 110 \
  --slave /usr/bin/g++ g++ /usr/bin/g++-11
gcc --version
g++ --version
```

After switching compilers, delete the old build directory and configure again so CMake does not reuse cached old compiler paths.

Qt DBus is optional. Distro Qt installs usually provide it with `qtbase5-dev`; if you use a minimal Qt install and enable Wayland/portal related code, make sure the Qt DBus development files are available.

### Optional Wayland/PipeWire Capture Dependencies

CMake probes these packages with `pkg-config`. When all are found, PipeWire/portal capture sources are enabled. Missing packages disable that path without blocking the build.

```bash
sudo apt install \
    libglib2.0-dev \
    libpipewire-0.3-dev \
    libspa-0.2-dev \
    libgbm-dev \
    libdrm-dev \
    libegl1-mesa-dev \
    libgl1-mesa-dev
```

## Third-Party Binary Packages

Large binary packages are not committed to the repository. Keep them locally under `third_party`:

- `third_party/webrtc`: Google WebRTC static package with the current architecture's `libwebrtc::linux_*_m144_*` target.
- `third_party/ffmpeg-builds/<package>`: FFmpeg 8.1 LGPL shared/dev package. If it is missing, the FFmpeg codec backend is disabled.
- `third_party/linux-runtime/lib`: optional private Linux runtime directory. CI builds libva with `tools/build_linux_runtime_libva.sh` and builds the PipeWire 0.3.65 client, modules, and SPA support on Ubuntu 18.04 with `tools/build_linux_runtime_pipewire.sh`. Their directory layout is preserved under `/opt/airan-desk/lib` and in portable packages.
- `third_party/linux-runtime/pipewire-sdk`: headers and pkg-config SDK generated by the PipeWire build. Add this directory to `CMAKE_PREFIX_PATH` to enable PipeWire when the system has no `libpipewire-0.3-dev` package.

See [dependencies.en.md](dependencies.en.md) for paths and download notes.

## Build with CMake Presets

Requires CMake 3.21+.
Presets use the configured `gcc` / `g++` names by default. If those point to compilers older than 11, update the system alternatives or override `CMAKE_C_COMPILER` and `CMAKE_CXX_COMPILER` from `CMakeUserPresets.json`.

```bash
cmake --preset linux-x64
cmake --build --preset linux-x64
```

arm64 / armhf:

```bash
cmake --preset linux-arm64
cmake --build --preset linux-arm64

cmake --preset linux-armhf
cmake --build --preset linux-armhf
```

## Cross-compile arm64 / armhf

Install cross compilers:

```bash
sudo apt install \
    gcc-aarch64-linux-gnu g++-aarch64-linux-gnu \
    gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf
```

Cross compilers must also be GCC/G++ 11+ level toolchains; old 7.x toolchains fail in the WebRTC m144 headers. The built-in `linux-arm64` and `linux-armhf` presets select the matching GNU cross compiler names and default sysroot paths. Override target Qt, sysroot, WebRTC, or FFmpeg locations from `CMakeUserPresets.json` when your local layout differs.

## Output and Install

Default output:

```text
out/build/linux-x64/release/airan-desk
```

The build output directory receives:

- `conf/`
- `locale/`, project translations.
- `translations/`, Qt system translations when found.
- FFmpeg `.so*` runtime files when the FFmpeg package is found.

### Build a portable package

`tools/build_package.sh` generates one portable package that can either run in place or be installed system-wide. It cannot be run without arguments and requires at least `--configure-preset`. The following command assumes WebRTC, FFmpeg, and private Linux runtimes have already been prepared:

Use this portable package workflow for Linux release artifacts. `cmake --build --preset linux-x64 --target install` is a developer/system install and does not generate a complete portable package.

```bash
bash tools/build_package.sh \
  --configure-preset linux-x64 \
  --build-preset linux-x64 \
  --portable-package-name airan-desk-linux-x64-portable \
  --portable-glibc-floor 2.27
```

The portable packager collects Qt Core/Gui/Widgets/Network/Svg/WebSockets, the Qt XCB and image plugins, FFmpeg when enabled, optional private runtimes, and their recursive ELF dependencies. It uses `patchelf` to assign relative RPATHs to the executable, private libraries, and plugins. Always run the package through its `./airan-desk` launcher. The launcher prepends `lib/`, `lib/codecs/`, and compatibility directories to `LD_LIBRARY_PATH` because the FFmpeg runtime, when enabled, is loaded by bare library name through `dlopen()`.

#### Choosing a glibc package

Check the target machine first:

```bash
ldd --version | head -n 1
```

Choose a package from the reported version:

| Portable package | Architecture | Target glibc | Common default distro versions | Codec difference |
| --- | --- | --- | --- | --- |
| `airan-desk-linux-x64-glibc2.17-portable.tar.gz` | x64 | 2.17 or newer; primarily for 2.17-2.26 | RHEL/CentOS 7 (2.17), Ubuntu 14.04 (2.19), Debian 8 (2.19), SLES 12/openSUSE Leap 42 (approximately 2.22), Ubuntu 16.04 (2.23), Debian 9 (2.24), Amazon Linux 2 (2.26) | Does not bundle the FFmpeg runtime; WebRTC builtin/Internal software codecs remain available |
| `airan-desk-linux-*-glibc2.27-portable.tar.gz` | x64, arm64, armhf | 2.27 or newer | Ubuntu 18.04 (2.27), Debian 10/RHEL 8/Rocky 8/AlmaLinux 8 (2.28), Ubuntu 20.04/Debian 11 (2.31), RHEL 9/Rocky 9/AlmaLinux 9/Amazon Linux 2023 (2.34), Ubuntu 22.04 (2.35), Debian 12 (2.36), Ubuntu 24.04 (2.39) | Bundles the FFmpeg runtime and probes runtime hardware codec availability |

The distro entries are common defaults, not runtime guarantees. Derivative distributions, vendor-maintained systems, and long-lived enterprise images may retain a different glibc version, so use the target machine's `ldd --version` result. glibc versions older than 2.17 are unsupported. CentOS 7, Ubuntu 14.04/16.04, and Debian 8/9 have exited normal security maintenance; binary compatibility does not make those systems appropriate for an Internet-facing deployment.

The 2.17 package can also run on systems with glibc 2.27 or newer, but newer systems should prefer the 2.27 package to retain the FFmpeg runtime and hardware codec probing. glibc is only one compatibility floor: the target still needs a compatible kernel, graphics driver, desktop session, and system services.

CI builds x64, arm64, and armhf `GLIBC_2.27` portable packages in Ubuntu 18.04 containers and the x64 `GLIBC_2.17` portable package in a CentOS 7 container. Each portable executable includes both the X11 and PipeWire/portal backends and points `PIPEWIRE_MODULE_DIR`, `SPA_PLUGIN_DIR`, and `PIPEWIRE_CONFIG_DIR` at the packaged runtime. A target Wayland desktop must still provide a running PipeWire service, `xdg-desktop-portal`, and its desktop-specific portal backend.

#### Reproducing CI locally

The GitHub runner is Ubuntu 22.04, but Linux artifacts are built inside their baseline containers. Building directly on an Ubuntu 22.04 host links against that host's glibc and does not produce an equivalent 2.27 or 2.17 compatibility package. The exact reproduction method is to run the complete `docker run` block for the corresponding job in `.github/workflows/build-packages.yml`.

Choose the Windows-hosted environment according to the goal:

- WSL2 with an Ubuntu distribution is sufficient for Linux x64 compilation, command-line tests, and general source validation against that distribution. Docker is not mandatory for this workflow. Clone the repository into WSL2's ext4 filesystem, such as `~/src/airan-desk`, instead of building under `/mnt/c` or `/mnt/d`, to avoid permission, case-sensitivity, and I/O performance differences.
- Reproducing the CI portable packages and their glibc floors requires a container engine. A direct WSL2 build links against the WSL distribution's own glibc and cannot replace the Ubuntu 18.04 or CentOS 7 baseline container. Use either Docker Desktop with its WSL2 backend or Docker Engine installed inside WSL2.
- WSLg is useful for basic GUI startup checks, but its virtual display, audio, `uinput`, systemd, PipeWire, and portal environment differs from a real Linux desktop. Validate screen capture, remote input, login autostart, and Wayland portal workflows on a real Linux desktop or VM as well.

Inside a provisioned Ubuntu 18.04 x64 container, build the 2.27 package in this order:

```bash
bash ./tools/build_linux_runtime_libva.sh
bash ./tools/build_linux_runtime_pipewire.sh
bash ./tools/prepare_third_party.sh "" linux linux-ubuntu18-x64-m144-gnu
bash ./tools/build_package.sh \
  --configure-preset linux-x64 \
  --build-preset linux-x64 \
  --portable-package-name airan-desk-linux-x64-glibc2.27-portable \
  --portable-glibc-floor 2.27 \
  --cmake-arg -DCMAKE_C_COMPILER=gcc-11 \
  --cmake-arg -DCMAKE_CXX_COMPILER=g++-11 \
  --cmake-arg "-DCMAKE_PREFIX_PATH=$PWD/third_party/linux-runtime/pipewire-sdk" \
  --cmake-arg -DAIRAN_REQUIRE_PIPEWIRE_CAPTURE=ON
```

Inside a CentOS 7 x64 container provisioned with devtoolset-11 and the Qt 5 build dependencies, use a conda-forge GCC toolchain. CentOS devtoolset-11 disables libstdc++'s dual ABI, while the bundled GNU WebRTC package requires the C++11 ABI:

```bash
source /opt/rh/devtoolset-11/enable
bash ./tools/build_linux_runtime_libva.sh
bash ./tools/build_linux_runtime_pipewire.sh
bash ./tools/prepare_third_party.sh "" webrtc linux-centos7-x64-m144-libcxx
curl -Ls https://micro.mamba.pm/api/micromamba/linux-64/latest \
  | tar -xj -C /usr/local/bin --strip-components=1 bin/micromamba
MAMBA_ROOT_PREFIX=/opt/micromamba micromamba create -y \
  -p /opt/airan-toolchain \
  -c conda-forge \
  gcc_linux-64=11.4.0 gxx_linux-64=11.4.0 sysroot_linux-64=2.17
conda_toolchain=/opt/airan-toolchain/bin
QMAKE=qmake-qt5 bash ./tools/build_package.sh \
  --configure-preset linux-x64 \
  --build-preset linux-x64 \
  --portable-package-name airan-desk-linux-x64-glibc2.17-portable \
  --portable-glibc-floor 2.17 \
  --cmake-arg -DWEBRTC_LINUX_COMPAT=centos7 \
  --cmake-arg -DWEBRTC_LINUX_STL=libcxx \
  --cmake-arg "-DCMAKE_C_COMPILER=$conda_toolchain/x86_64-conda-linux-gnu-gcc" \
  --cmake-arg "-DCMAKE_CXX_COMPILER=$conda_toolchain/x86_64-conda-linux-gnu-g++" \
  --cmake-arg -DCMAKE_SYSROOT=/ \
  --cmake-arg "-DCMAKE_EXE_LINKER_FLAGS=-B/usr/lib64 -L/usr/lib64 -Wl,-rpath-link,/usr/lib64" \
  --cmake-arg "-DCMAKE_PREFIX_PATH=$PWD/third_party/linux-runtime/pipewire-sdk" \
  --cmake-arg -DAIRAN_REQUIRE_PIPEWIRE_CAPTURE=ON
```

Both packages are written under `out/packages/`. The packager scans every ELF in the final package. If any file requires a glibc version above the declared floor, the build fails instead of producing or uploading a mislabeled artifact.

Every portable package also contains `install-linux.sh` and `remove-linux.sh`. Run `./airan-desk` in place, or use `sudo ./install-linux.sh` to install desktop integration, autostart, the uinput rule, and the same private runtime.

To enable the portable PipeWire build manually on the Ubuntu 18.04 baseline:

```bash
bash tools/build_linux_runtime_pipewire.sh
cmake --preset linux-x64 \
  -DCMAKE_PREFIX_PATH="$PWD/third_party/linux-runtime/pipewire-sdk" \
  -DAIRAN_REQUIRE_PIPEWIRE_CAPTURE=ON
```

The portable package does not bundle glibc, the Linux kernel, OpenGL/EGL, DRM/GBM, Vulkan/CUDA, the system PipeWire service, or hardware drivers. Its launcher checks `60-airan-desk-uinput.rules`; when the rule is missing or outdated, it requests administrator privileges to install it and then asks the user to log out and back in or restart.

The system-installed and portable launchers use the same uinput checker. It ensures that the `input` group exists, adds the launching user to that group, loads the uinput kernel module, reloads udev, and waits for the device node. A desktop session requests privileges through `pkexec`, while an interactive terminal falls back to `sudo`. New supplementary-group membership reaches the application only after logging out and back in or restarting. If elevation is unavailable or the running kernel has no uinput module, the application still starts and displays a remediation message. `-v`, `-V`, and `--version` never trigger installation; automation can set `AIRAN_DESK_SKIP_UINPUT_SETUP=1`.

Install to the system:

```bash
sudo cmake --build --preset linux-x64 --target install
sudo udevadm control --reload-rules
sudo udevadm trigger
```

`install` installs:

- The executable to `${CMAKE_INSTALL_BINDIR}`, `/opt/airan-desk/bin` by default.
- FFmpeg and optional third-party Linux runtime libraries to `${CMAKE_INSTALL_LIBDIR}`, `/opt/airan-desk/lib` by default.
- The desktop entry to `${AIRAN_SYSTEM_DATADIR}/applications`, `/usr/local/share/applications` by default.
- The current-user autostart template to `${CMAKE_INSTALL_DATADIR}/airan-desk`.
- The `uinput` udev rule to `/etc/udev/rules.d`; override with `-DUDEV_RULES_INSTALL_DIR=...`.
- Icons, default config, project translations, and Qt translations.

Enable current-user autostart:

```bash
mkdir -p ~/.config/autostart
cp /opt/airan-desk/share/airan-desk/airan-desk-autostart.desktop ~/.config/autostart/airan-desk.desktop
```

Disable autostart:

```bash
rm -f ~/.config/autostart/airan-desk.desktop
```

## Runtime Configuration

Edit `conf/common.ini` before running:

```ini
[signal_server]
wsUrl = wss://your-signal-server.example/ws
```

Run from the build output directory:

```bash
cd out/build/linux-x64/release
./airan-desk
```

Headless mode:

```bash
./airan-desk --no-ui
```

Run the remote desktop process inside a real desktop session when possible. That session carries `DISPLAY` / `WAYLAND_DISPLAY` / DBus environment values needed by capture and input paths.

## FAQ

### CMake Is Too Old or Does Not Recognize `--preset`

This is a version limit. Upgrade to CMake 3.21+ and build with presets.

### GCC 7.5 Fails in WebRTC Headers with `non-constexpr`

The current WebRTC m144 headers need newer GCC C++20 support. Upgrade to GCC/G++ 11+, then reconfigure from a clean build directory:

```bash
rm -rf out/build/linux-x64
cmake --preset linux-x64
cmake --build --preset linux-x64
```

### Qt5 Svg or WebSockets Not Found

```bash
sudo apt install libqt5svg5-dev libqt5websockets5-dev
```

### Qt translations Not Found

Distro Qt commonly installs them under `/usr/share/qt5/translations`. If auto-detection fails, set `AIRAN_QT_TRANSLATIONS_DIR` from `CMakeUserPresets.json`.

### FFmpeg Backend Is Disabled

Make sure `AIRAN_FFMPEG_ROOT` points to an FFmpeg shared/dev package containing `include/` and `lib/`. If it is absent, the application uses WebRTC's internal codecs.

### Keyboard/Mouse Injection Fails

Install the uinput rule and reload udev:

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Log out and back into the desktop session before testing again.

### Wayland Capture Fails

Install the optional PipeWire/portal development packages, reconfigure, and run inside a real desktop session. Avoid starting desktop capture directly from SSH or a system service.
